## 后续安排与边界

- **开发/管理分工**：角色、许可权、用户授权及 Process Definition/进程组/Scheduler 管理归将来的 ps-admin skill，不作为 ps-cli 社保复刻的待补开发能力；AE 程序、Field XLAT 和 AD Project 迁移仍在 ps-cli 范围。已有配置及权限是运行验收前置条件，不因边界调整而绕过校验。

- **Page 小批次交付**：沿用用户 2026-10-27 确认的每批 10–20 属性安排；先收集原生/AD 证据，再实现并验收。没有依据的属性暂不支持，不自动穷举。Fluid 暂缓。
- **SOAP 未关闭问题**：Validation=Y 间歇性 119,40 仍需定位；已通过的 SOAP 1.1/1.2 调用使用 Validation=N。该问题保留并在后续小版本跟进，不能擅自关闭现有业务接口的校验。
- **已明确后置**：SOAP Consumer/异步、CI 引用和 CI 多语言子结构；后者不包括已完成的 Message Catalog 翻译。未开放的整份定义或门户文件夹删除见对象文档，不再将空 Service 删除列为待实现。
- **迁移验收**：当前门户解耦和读写拆分的跨环境实际删除尚未证明；检查导出保留 Delete 键只证明清单完整。
- **目标版本**：其他版本含 8.54/8.55 按实际目标编译和功能核验；未验证不等于不支持，不以 8.57 作为安装硬门槛。JSON 后端的默认切换门槛不是整个 CLI 的版本认证。
- **首次安装**：1.5.0 空白环境首次安装已因无可用环境延期至首次真实部署；同环境比较/回导、依赖检查和健康检查保留为已有证据。
- **安装体验（2.0.2）**：根目录install.example.json以environments容纳多个环境，各自填写登录地址、用户名/密码，active_environment选择当前环境或留空保留。Agent对全部输入校验后一次合并正式配置，按环境分别部署验收，并发现AD与目标版本；节点固定默认PSFT_HR，已有自定义配置保留。填写副本排除于Git/同步/打包。panwx25已原生生成C_PSCLI_READ / C_PSCLI_WRITE许可权及配套角色，许可权随核心工程、角色DAT配套交付。安装仅提醒用户或管理员自行分配角色，不从配置选择角色或自行授权。2.0.3 已包含原生工程角色及 8.55 同批 DAT 补导路径的跨环境验证，保留原有用户关联；不把交付检查视为当前用户授权验证。
- **安装续装（2.0.2）**：完全空白示例自动跳过、已填写环境严格检查；重复准备/合并保留用户输入及未变化的配置。安装助手 run 使用限定环境的私有临时配置执行有时限的验收，不切换正式当前环境。下载/运行环境/部署工具缺失及阶段恢复纳入 Agent 流程。当前验证为本地隔离行为，干净机器及全新 PeopleSoft 环境的端到端安装仍待实测。
- **历史环境**：jt-dev 的错误应用包工程条目未清理，不能据 panwx25 修复宣布原环境已解决。

## 后续版本的检查

1. 按最终承诺范围核对功能矩阵：查找/分页、属性与子对象、关联/权限、错误及部分成功处理、删除与迁移语义；对遗留问题明确关闭或经用户调整范围。
2. 对最终改动运行相应 CLI/API 回归；影响界面/行为的内容补 AD/PIA 验收，报告具体环境和未验证范围。
3. 原生导出完整工程及编译内容，检查依赖、Handler、TOOLSREL 与日志；XML/INI 包括来源地址在内的全部字节保持原样，交付前与 AD 原文件核对哈希，不做内容替换。在可恢复的验收环境执行适用的比较/回导和工作流。不能把导入成功等同于接口已授权。
4. CLI、文档、原生工程、release 镜像、安装副本与新发行包保持同一基线；保留历史包，区分已修复、已验证和后置事项。

## 编号规则

2.0.0 为前一正式基线，2.0.1 汇总其后已验证的修复和开发工作流；后续兼容性修复按 2.0.x 修订号发行，后续功能按范围使用 2.x 小版本。需要候选验证时使用对应的 rc 编号。接口不兼容调整须说明迁移方式；新增对象本身不必改变既有契约。

1.5.0 沿用已有标签 `v.1.5.0`；本地旧 `2.0.0～2.4.2` 为未公开内部实施编号，不是已发布版本。当前 GitHub 状态以实际 Release 为准，本地工作区和 zip 文件名不能替代发行记录。
