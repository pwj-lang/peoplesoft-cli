# 安装时的信息发现与填写

本文件供 Agent 使用，完整顺序见 [INSTALL.md](../INSTALL.md)。面向任何首次安装开源 Skill 的用户：用户在项目提供的通用填写副本中填目标和用户名/密码，Agent 据此生成对应环境配置。讨论安装体验本身不授权创建某个示例环境。执行工具、判断比较结果、编译与验收由 Agent 完成。

## 先发现，再确认

`python scripts/install_helper.py discover` 只读输出已有环境凭据是否存在、AD 路径/文件版本及发现来源，不读取进程 CommandLine。Windows 搜索已有 pside 进程、PATH、App Paths、PS_HOME、常见安装目录与桌面/开始菜单快捷方式，不默认全盘递归。未知安装位置才补充定向搜索。

AD 文件版本、目录提示和目标服务器版本分别记录。优先读取目标已登录 PIA 的版本信息、目标 AD 登录会话，或通过目标已存在且获准使用的只读入口读取 PSSTATUS.TOOLSREL。PSSTATUS 的精度不足以替代补丁证据；不要为了判断 JSON 后端要求用户补查小版本。`#ToolsRel` 返回编译环境的完整版本，不能从数据库里显示 `8.55` 就推断编译器一定按 `8.55.00` 取分支，见 [Oracle #ToolsRel](https://docs.oracle.com/en/applications/peoplesoft/peopletools/8.63/peoplecode-language-reference/toolsrel.html)。

将“发现目标为 8.55，找到此 8.55 客户端，准备使用它”并入一次环境确认；目标已经明确且证据一致时直接继续，不逐步要求确认。只有本机证据时显示“找到这些客户端，目标版本尚待登录核实”，不能写成已检测到目标版本。没有补丁证据也可先进行原生兼容性检查。若原生工具明确拒绝某版本/对象，保留原始错误，停止该具体步骤并判断可用范围，不篡改 TOOLSREL 或编译块。

**节点按本工具的安装约定固定默认使用 `PSFT_HR`。** 模板不含 node，Agent 不询问、不自动发现、不等待节点确认，也不为读取节点增设自举程序。填写基本信息后即可生成正式环境配置。

已有环境的自定义 `node` 保留；用户已明确提供其他节点时可用高级参数 `--node` 覆盖。这是有需要的用户自行使用的高级用法，不进入普通安装流程，不据此要求所有人先确认节点。

“Unable to find a Routing”仅说明当前请求未匹配到可用路由；须继续核对入口、节点、别名/版本、Active、Handler 与工程现状，不能据此断言工程不存在。目标里已有可用节点时复用，不迁移/覆盖整套系统节点。

## 私有填写文件

这些命令由 Agent 执行。先安装与所选发布基线相符的助手；历史包没有助手时，Agent 以同样的私有文件流程完成。

```powershell
python scripts/install_helper.py prepare
python scripts/install_helper.py check
python scripts/install_helper.py apply
```

通用模板是项目根目录 [install.example.json](../install.example.json)，模板随开源项目交付，提供 dev / uat 两个空白示例块。`environments` 用环境名作为键，每个环境只填写登录地址、用户名和密码；只填需要的环境，不用的块全部留空即可自动跳过，也可复制、改名、删除块。空对象也会跳过；未知字段有内容时不能当空白示例静默忽略。`active_environment` 填要选中的已填写环境名，留空则保留原来的当前环境；首次安装留空时选第一个填写完整的环境。填写文件不选择或控制访问权限，旧文件中的 access_mode 也不代表服务器授权。

`prepare` 不要求先给环境名或地址，默认生成同目录的 `install.local.json`，它才是用户填写的副本。Agent 已知一个目标时可用可选参数预填成单环境块，不跨环境复制密码。**只给实际填写副本的可点击链接，不让用户编辑公开模板。** 已有填写副本直接返回原路径和 existing 状态，不报错或重建覆盖。安装目录只读时可用 `--file` 在用户私有目录生成同样的通用副本；不为此要求用户掌握文件操作或命令。

给出实际文件的可点击链接，对用户说：“已准备好安装填写文件。只填需要的环境登录地址、用户名和密码，不用的全部留空；active_environment 也可以留空。填好保存后告诉我。”不要求用户把这些信息再贴到聊天里，不向用户展示执行命令。支持 UTF-8 BOM 和完整登录页地址；JSON 特殊字符用标准转义。格式有误时 Agent 先通过不回显秘密的解析定位并修复明确的结构问题，不猜测或自动修改密码；确需用户补充时只指出环境和字段，不输出密码行、配置正文或解析异常原文。

`check` 跳过完全空白的环境并在 skipped_environments 中列出名称，对其余环境逐项校验；任何字段填了一部分就必须补齐，password 缺失、空字符串、null 或纯空格都会报缺密码，有内容的密码原样保留。整份文件完全空白时提示至少填写一个环境，不能报告 ready。重复环境名、缺项或选中空白环境的 active_environment 都明确报错。只报告连接信息是否齐全，并提醒用户或管理员自行分配角色；不选择角色、不执行授权，也不代表已登录。`apply` 先校验全部已填写环境和所有同名地址冲突，再一次写入合并后的配置，备份一次原配置；任一已填写环境失败时全部不写。新环境节点均默认 `PSFT_HR`，已有自定义节点、附加字段及未出现在填写文件中的其他环境保留。

当前环境优先采用填写文件中的非空 active_environment，留空保留现有当前环境，首次安装留空选第一个填写完整的环境。高级 `--activate <环境名>` 可显式覆盖选择；不带值的旧用法继续支持。重复 apply 在合并结果未改变时返回 changed=false，不重写配置、不备份、不清缓存；只切换当前环境不清各环境缓存。旧版单环境平铺填写文件也继续兼容。填写副本留在本机，未获用户要求不自动删除。

生成本地多环境配置后，Agent 对每个填写的环境分别登录、导入及验收，按环境记录结果；不能把本地批量写入成功当作所有服务端部署成功，也不能把一个环境的版本或权限结论套给其他环境。

`run --environment <名称> current|auth|preflight|healthcheck` 使用私有临时单环境配置执行限定的读取检查，结束或异常后清理，不改变正式配置中的当前环境。默认单次请求上限15秒、整个子进程上限180秒，可用 --request-timeout / --timeout 调整；令牌/探针自己的短超时仍生效。healthcheck 支持 --page / --component / --record / --field / --query-record / --query-field 选择目标实际对象。该入口不接受定义写入或 SQL DML，也不代替原生部署。

同一环境内默认复用一组用户名/密码用于 CLI、PIA 和 AD，不同环境可以有各自的用户名和密码。AD 使用 PeopleSoft 用户登录并不等于要求用户另提供 Oracle Access ID 密码。目标原生登录实际失败或权限不足时才说明具体差异，必要时在同一私有目录生成另一个填写文件，不要求用户在聊天里选择密码传递技术方案。

实际填写文件和备份都是本地明文。项目内仅 `install.local.json` 允许作为填写副本，由助手限制为当前操作系统用户访问；`.gitignore`、同步和打包工具均排除此文件。同步时保留各安装目录自己的填写副本，不传播或覆盖。公开模板不含凭据，正式运行配置和备份仍保存在项目外的用户目录。不承诺 Agent 无法读取，也不把明文称作加密。脚本只返回 presence/状态；不 cat 文件，不打印 HTTP Authorization、Token、含密码的进程参数或异常对象。原生 AD 使用 `-CP` 时本机进程参数可能可见，读取到变量并不能消除此限制。Data Mover 可使用自动消费删除的私有参数文件，见 [Oracle 原生命令](https://docs.oracle.com/cd/E92519_02/pt856pbr3/eng/pt/tlcm/task_UsingthePeopleSoftDataMoverCommand-LineInterface-077ae3.html)。

## 常见卡点与续装

| 情况 | Agent 处理 |
|---|---|
| 只填 dev，uat 全空 | 跳过 uat，仅安装 dev；不要求用户删除示例块 |
| 地址/用户名已填，密码没填 | 一次列出所有已填写环境的缺项；不猜密码、不部分写配置 |
| Python 命令不可用 | 发现其他可用解释器并固定路径；确实缺少时准备官方运行环境，不默认安装 pip 依赖 |
| 下载无进度或断网 | 限时、有限重试，复用已校验缓存；恢复后接着下载/安装，不让用户手动下载解压 |
| 已有同名环境指向另一个地址 | 保留原配置，集中说明具体名称冲突；不能覆盖或随意另建名字掩盖目标歧义 |
| 没找到 AD 或数据库连接 | 定向发现已有客户端、AD 配置及 Oracle 连接别名；仍缺失时只说明所需工具/部署机器，不让用户抄命令 |
| 登录拒绝、缺角色或权限 | 分别说明密码需要核对、角色待用户/管理员授权；不循环重试同一密码，不自助授权 |
| JOB 等示例对象不存在 | 发现目标已有对象并替换验收参数，不把应用产品差异误报为安装失败 |
| 重复安装/会话中断 | 保留填写文件；未变化的配置不重写，核实目标阶段后从未完成处继续，已有角色不重复导入 |
| 多环境中的一个失败 | 继续其他环境的独立工作；每个环境记录版本、阶段、下一步及待用户事项，保留用户的当前环境选择 |

在用户私有数据目录持续保存安装阶段与证据位置；只记录可恢复所必需的信息，不保存密码/Token。用户回来只需说“继续安装”，Agent 自己读取记录并核对目标现状，不要求用户重填已保存信息或解释上轮日志。网络恢复或角色授权完成后先重验失败步骤，不把本地“做过”记录视为远端仍成功。

## 预置许可权和角色

工具自身的安装安全定义属于 ps-cli 交付范围；这不增加通用角色/许可权管理 API，其他日常管理仍归 ps-admin。

| 角色 | 绑定许可权 | 范围 |
|---|---|---|
| `C_PSCLI_READ` | `C_PSCLI_READ` | PSTOKEN_GET 和本工具 20 个读取操作，包括数据/SQL 读取；不含定义写入 |
| `C_PSCLI_WRITE` | `C_PSCLI_WRITE` | 上述读取 + 16 个定义维护操作；不含 SQL 写执行 |

常规安装只提醒：“请用户或管理员按需要自行分配 C_PSCLI_READ（只读）或 C_PSCLI_WRITE（读写）角色，完成后告诉 Agent 再验证。”安装助手不选择角色、不修改角色成员、不自行给当前用户名授权；实际权限由目标系统的授权决定。两个预置角色不包含用户、不含动态成员规则、不允许自助授权其他角色。不为通过健康检查扩大权限。已有其他角色的权限会累加；只读角色不会撤销已有写权限。两套预置列表还分别包含系统 `MESSAGE_CATALOG_CI` 的 Get/Cancel，以及 Get/Cancel/Create/Save/AddMessage/DeleteMessage 方法权限，配合各自的消息目录读写操作使用。

当前维护工程 `C_META_DATA_PKG` 同时包含两套许可权（类型 53）和两套角色（类型 19），角色仅关联各自的工具许可权，描述为 PsCli读取/写入许可权、PsCli读取/写入角色。8.60 原生 XML/INI 及配套 DAT 全部按原始字节交付。目标导入后分别回读角色和许可权，不能只凭 Copy 成功判断角色已迁移。

8.55 原生 AD 的 Copy From File 实测会跳过 XML 中的两套角色，尽管工程清单保留它们；此时使用同包 `assets/security/pscli-roles.dat` 与 `roles-import.dms` 完成原生补导。DAT 仅含两条 PSROLEDEFN 和两条 PSROLECLASS，不含用户成员；导入前备份并检查同名定义，已有同名定义更新须在授权范围内，模板使用 UPDATE_DUPS 更新导出的记录，不删除其他关联或用户。导入后核对描述、许可权关联及原有用户成员未变。两端基础语言不同时，Data Mover 自动把描述映射至基准表或相关语言表；应按用户显示语言核对有效描述，不能只查询 PSROLEDEFN.DESCR 判断导入失败，也不改写 DAT 的 BASE_LANGUAGE。角色已由原生 Copy 正确迁移时不重复补导。较旧稳定包仅配套 DAT，按其实际交付处理。语言映射机制见 [Oracle Data Mover IMPORT](https://docs.oracle.com/cd/E92519_02/pt856pbr3/eng/pt/tlcm/langref_UsingPeopleSoftDataMoverCommands-077ad8.html)。

已有部署权限时由 Agent 完成定义导入；缺少权限时提醒管理员处理，不绕过权限自举。定义导入不等于给用户名授权。Oracle 的 [旧版迁移说明](https://docs.oracle.com/cd/E92519_02/pt856pbr3/eng/pt/tlcm/task_UsingtheUpgradeWorkspace-0773e7.html) 也区分可复制到数据库与可复制到文件的定义类型；不把旧版客户端限制泛化为所有版本的 Project 均不能包含角色。

来源创建、导出检查与目标迁移验收分开记录。在目标导入后独立核对许可权操作、角色关联、无用户成员和 SQL 写执行关闭；最后让用户/管理员分配角色并用该用户名验证。不要依赖尚未授权的 API 完成自身初始授权。
